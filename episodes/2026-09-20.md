[curious] Better agent scaffolding is one thing. Knowing which bit helped is another. A new harness study holds the execution loop fixed and changes components independently: a hundred and seventy-six matched settings across four models, on SWE-Bench Verified and Terminal-Bench two point one. Five context-management strategies meet four window budgets. As space tightens, managing context helps mainly by preventing overflow failures. Not cleverer reasoning. Fewer crashes into the ceiling. [confident] The most efficient approach removes content using rules before asking a model to summarise; making removed content recoverable adds machinery the models rarely use, without improving accuracy. Planning helps weaker models get answers right, but mainly saves stronger models money. And models already good at bash can use just that interface at substantially lower cost; weaker ones benefit from predefined tools. I'd read this for the controlled comparisons. [serious] There are no accuracy or cost figures attached to those claims, and no replication yet. With the loop fixed, it tells you about components inside that design, not the best possible agent.

[curious] Once you've got an agent that can keep going, where does it get worthwhile practice? Scientific repositories contain plenty, but a passing test isn't necessarily sound science. Science I-D-E uses expert-defined cases and acceptance criteria to turn repositories into executable environments where agents can attempt tasks and verify results. Verified runs then train the PhAI I-D-E family, at seventy-two billion, nine billion and four billion parameters, using supervised examples and reinforcement learning — learning from rewards. The authors claim gains on held-out scientific-code repair and selected general-purpose benchmarks. [serious] Without gain figures or named baselines, the transfer claim isn't persuasive yet. The code's public, though; the environments are the bit I'd inspect.

[curious] Verification gets stranger when the answer is somebody else's motive. Google's Fuse assigns a hidden motive to a simulated agent, then has another agent recount the encounter to the assistant being tested. So there's a known answer, but the assistant hears a subjective version. Across twelve language models, Google finds that this mediation makes inference harder: biased framing sways answers, and models can need more detail than humans. Longer conversations don't reliably help. [confident] This one I'd take seriously as an evaluation design: twenty-four thousand human annotations check simulation faithfulness, and the framework comes with twenty-one thousand open examples. But knowing the assigned motive doesn't establish that real people behave that neatly; effect sizes aren't given.

[long pause] [serious] Even a formally checked answer can rest on an unreliable checker. The new challenge to the Navier-Stokes proof we covered earlier concerns verification, not credit. On LessWrong, Milo Moses points to bugs in Lean four's kernel, the trusted code that checks proofs, which can let false statements pass. One involved a missing check on a variable that wasn't bound. He says a Lean research organisation's search with OpenAI found six new soundness bugs and prompted security changes. [curious] His strongest concern is that an agent chasing an impossible proof might discover an exploit instead. He puts seventy-five percent odds on a major formalised theorem being retracted over an agent-exploited bug. That's his forecast, not an observed retraction. He still thinks this proof is likely correct; independent review of the mathematics remains unfinished.

[curious] And where answers aren't so crisp, can competing arguments improve oversight? On LessWrong, Sam Martin and colleagues find no uplift from debate on Geoguessr or a pairwise-scoring variant of L-M-C-A; they use selection from multiple candidates as a stand-in for debate training, so actual training with published scores is the test still needed, not something this qualitative negative result settles.

[confident] I'd change one harness component before rebuilding the lot. And before trusting a green verification tick, check what can make the checker wrong.
